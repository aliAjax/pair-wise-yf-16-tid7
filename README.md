# hxyfront-62004 滑雪板调校维护

面向滑雪板调校店的装备维护前端：维护工单、底板修补与完工排程接成**一份可重排队列**。

## 排程规则

- **打蜡 / 修边可并行**：各 2 个工位（容量 2）
- **底板修补同一时间只占一个专用工位**（容量 1），P-Tex 修补串行
- 同一工单按 `底板修补 → 修边 → 打蜡` 串行（无底板损伤跳过修补）
- **工位容量不足时排队**，优先级：加急 → 原承诺时间 → 队列先后
- **加急单插入队首**后，其后所有未锁定工单重算完工时间
- **已开始 / 已承诺工单的时段锁定**，重排不移动；未开工工单不允许排进过去
- 确认排程后所选工单转为“已承诺”并锁定当前时段，退出可重排队列
- 推进工作台时钟：跨过开工点自动锁定为“进行中”，跨过完工点出队为“已完工”

## 确认 / 撤销 / 写入失败续传

- 加急切换、新工单登记都是**草稿**，只有点“确认排程 / 推进时间”才形成新版本
- **撤销**：丢弃草稿与未完成写入，恢复到上次确认状态
- 确认状态切块写入 localStorage（每块 4KB）：
  - 块先写 staging，全部成功后才发布并提交 manifest，因此写入中途失败时读到的永远是上次确认状态
  - 写入失败停在失败块，界面出现“从第 N 块继续重试”按钮，**从那里继续重试**
- “故障演练”按钮可注入 1–2 次写入失败，演示断点续传

## 完工联动

- 完工后**刃角参数表**与**客户历史维护记录**都按当前这版排程展示工序时段与完工时间
- 参数表支持完工状态筛选（全部 / 排队中 / 进行中 / 已承诺 / 已完工）

## 技术栈

React 19 + Vite 7 + TypeScript，纯函数排程引擎，状态持久化到 localStorage。
